# NoorQuran 0.5 quality and release gates

## Findings from source review
- Critical: audio selection was kept busy by awaiting the entire recording playback. Changed to start playback without blocking UI, with completion/error feedback.
- High: Mushaf page metadata must reject out-of-range verse identifiers. Added range checks and navigable error screen.
- High: printed 604-page layout is only verse-start based, not word/line-accurate; do not advertise a printed-Madinah facsimile.
- High: reciter audio is not bundled and selected audio does not synchronize with ayahs. Explain this in UI.
- High: tafsir, hadith, and word-by-word content are not verified/complete; never replace them with unreviewed text.
- High: Quran text validation verifies structure, not independent word-for-word accuracy against an approved checksum.
- High: shared_preferences backup is not encrypted; do not include secrets, phone numbers, or credentials.
- High: Android project is generated by flutter create in CI. Pin and commit reviewed Android manifest, signing, and release configuration before production.
- High: release artifact is unsigned with a stable production upload key unless separately configured. Ensure future updates can be installed over previous releases.
- High: accessibility (TalkBack, scalable Arabic fonts), RTL, screen rotation, Android 10/11/12/13/14/15 and low-memory devices need real-device checks.

## Acceptance criteria before calling a release production ready
1. Fresh install and upgrade on real Android phones; offline Quran opens every surah and sampled pages 1, 2, 100, 300, 604.
2. Quran bundle matches independently verified Tanzil version and checksum; source/license notice is visible.
3. Audio MP3 and M4A can be selected, paused, resumed, stopped and repeated; canceled picker leaves usable controls.
4. Bookmarks, reading position, memorization, backup and restore survive process death and app update.
5. No unwanted network calls, invasive permissions, leaked personal information or crash logs containing private data.
6. Flutter analyze, Flutter tests, Android release build, APK install smoke test, and device QA all pass.
7. License audit of every redistributed Quran, recitation, translation, tafsir, and hadith data file.
8. Reproducible signed production builds, stable application ID and controlled signing-key backup.

Automated CI passing is necessary but not sufficient for a 10/10 score.
